# 知阁 Zhige 毕设答辩演示脚本

> 面向答辩现场的逐环节演示脚本。每一步都给出「做什么 → 操作 → 预期结果 → 讲解要点」。
> 当前环境：Python 3.11 venv，生成式 LLM 走 WorkBuddy 网关（deepseek-v4.1-flash），
> 向量走本地 ONNX BGE，已装 OCR（RapidOCR）与 bge-reranker-base 重排。

## 1. 主线演示（按这个顺序，逻辑最顺）

### 环节 1：上传文档 → 入库（对应"文档解析 + 分块 + 向量化"）

**操作**：Web 界面点「上传文档」，选一个 PDF 或 Markdown；或用 API：

```powershell
curl.exe -sS --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/ingest -F "file=@E:\project\Dtou\agent\data\raw\00000000\员工手册.md"
# 预期：{"docs":1,"chunks":3,"ingested":3,...}
```

**讲解要点**：
- 这条链路做了「解析 → 元数据增强 → 清洗去重 → 数据准入 → 中文分块（400 字/50 重叠）→ 本地 ONNX BGE 向量化 → 写入 Chroma + BM25」。
- 强调"混合检索"：同一份文档同时进向量库（语义）和 BM25（关键词），不是单一向量。

---

### 环节 2：检索问答（生成式 + 引用溯源，这是核心）

**操作**：

```powershell
curl.exe -sS --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/chat -H "Content-Type: application/json" -d "{\"query\":\"总结一下员工手册里公司简介和报销制度\",\"top_k\":6}"
```

**预期**：返回一段**生成式综合回答**（不是照抄原文），句尾带 `[2]` `[3]` 引用，`sources` 里有原文分块和 `score`。

**讲解要点**：
- 这不是"关键词匹配"，是「向量+BM25 → RRF 融合 → 重排 → 大模型生成 → 引文校验」五步。
- 重点讲**引文校验（verification）**：`verified: true` 说明答案的每句都能回溯到原文片段，能挡"带引用的编造"。
- 现场追问一句：再发一条同一会话的追问（带 `session_id`），展示**多轮记忆**。

---

### 环节 3：无关问题拒答（证明"不编造"）

**操作**：

```powershell
curl.exe -sS --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/chat -H "Content-Type: application/json" -d "{\"query\":\"今天北京的天气怎么样\",\"top_k\":4}"
```

**预期**：返回「无法获取实时天气…」的拒答，`sources` 为空，没有硬编。

**讲解要点**：这是本项目的关键设计——检索分数低于阈值就直接拒答，而不是硬答一篇无关原文。对比一般"什么都敢答"的 demo，这是加分项。

---

### 环节 4：知识图谱（展示 GraphRAG 能力）

**操作**：

```powershell
# 实体关系抽取
curl.exe -sS --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/kg/extract -H "Content-Type: application/json" -d "{\"text\":\"知阁科技成立于2021年，总部位于杭州，创始人张三曾任阿里巴巴技术专家。\",\"source_doc\":\"demo\",\"persist\":true}"

# 查看图谱规模
curl.exe -sS --noproxy '*' http://127.0.0.1:8000/api/v1/kg/stats
```

**预期**：`entities` 返回 Organization/Location/Person 等分类实体，`relations` 返回 LOCATED_IN / FOUNDER_OF 等关系；stats 显示实体/关系计数增长。

**讲解要点**：讲清"向量检索只能找到相关片段，知识图谱能回答'谁和谁什么关系'这类多跳问题"。提一句 SQLite/Neo4j 双后端 + Cypher 注入防护。

---

### 环节 5：扫描件 OCR（证明"文档真的进得来"）

**操作**：

```powershell
curl.exe -sS --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/ingest -F "file=@E:\project\Dtou\agent\data\raw\00000000\扫描件测试.pdf"
```

**预期**：`{"docs":1,"chunks":1}`，随后提问能命中这张"图片型 PDF"里的文字。

**讲解要点**：这是一张**纯图片、无文本层**的 PDF，系统用 RapidOCR 逐页识别补全文字。重点讲"混合型 PDF 逐页补齐"——正文能提的照常提，扫描页才走 OCR。

---

### 环节 6：直连 LLM 开关（通用问答 vs 本地知识库）

**操作**：Web 界面顶部「直连 LLM」开关。

- **关闭（默认，本地知识库模式）**：知识库内问题 → 检索 + 重排 + 大模型生成（带原文引用）；知识库外/寒暄问题 → 明确拒答（不编造）。
- **开启（直连大模型）**：跳过检索，把问题直接发给 deepseek-v4.1-flash（走你的 key）做通用问答，像 ChatGPT 一样直答，无引用。

**现场演示（三连问，对比最直观）**：

1. 关闭开关，问「青花瓷手机的处理器是什么？售价多少？」→ 综合回答带 `[1]` 引用，`verified: true`（检索增强）。
2. 打开开关，问「你是谁？」→ 大模型直答「我是由深度求索公司创造的 AI 助手…」，不再是模板。
3. 关闭开关，问同样「你是谁？」→ 回到「我是小识，本地知识库助手…」模板拒答，对比明显。

**讲解要点**：这一个开关就是「RAG（检索增强）vs 纯 LLM（零检索）」的分水岭——同一个大模型，接上知识库就"有据可依、可核验"，断开知识库就退化成通用聊天机器人。API 侧对应请求体/WS 里的 `direct` 字段（`true`=直连，`false`=本地知识库）。

## 2. 答辩高频问题与回答

| 问题 | 回答要点 |
|------|----------|
| 你的创新点是什么？ | ① 无 LLM 也能跑的 extractive+ONNX 混合检索；② 混合检索 RRF 融合 + 父子索引 + 多路召回；③ 引文可验证 + 相关性兜底拒答（防编造）；④ d1 决策层（noul/choice/score 原语）抽象 |
| 和 RAGFlow/Dify 比呢？ | 它们是企业级广度（多向量库/IM/MCP），我是"个人与中小企业零门槛本地化"；优势是开箱即用、无 GPU 可跑、引文可核验 |
| 检索怎么保证准确？ | 混合检索（BM25+向量+RRF）→ 重排 → 多路召回 → 引文校验，四层保障；现场演示拒答即可 |
| 为什么没登录/多用户？ | 定位是本地单机工具，刻意去除账号门槛；数据归属见 identity.py，多用户可后续接认证 |
| 知识图谱/重排为什么默认关？ | 可选能力，装依赖即开；默认关是为了零门槛启动（不强制下 GB 级权重） |
| 数据安全/隐私？ | 文档、向量、模型全在本机；生成式走自建网关，不外泄到第三方 |

## 3. 应急预案

- **现场断网**：生成式挂了就切回 `extractive`（无 LLM 原文摘录），照样能演示检索+引用，讲"离线可用"反而加分。
- **网关 401/400（11-128）**：WorkBuddy 上游偶发"未授权渠道"，重试或换模型（`deepseek-v4-pro` / `glm-5.3`）。
- **重排太慢**：把 `config/local_overrides.yaml` 里 `reranker.enabled` 临时改 `false`，问答秒回；讲到重排时再现场开一次。
- **端口被占**：`Get-NetTCPConnection -LocalPort 8000 | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }`。

## 4. 一句话定位（开场白备用）

> 「知阁是一个开箱即用的本地中文知识库 RAG 平台：上传文档 → 自然语言提问 → 得到带原文引用的答案，数据全程留在本机。区别于通用问答的是，它强调**可核验**——每条答案都能回溯到知识库原文，检索不到就明确拒答，而不是编造。」
