# 小白视角问题清单与修复记录

> 测试视角：一位完全不了解 RAG、不了解本项目的普通用户（"小白"），第一次使用本系统。
> 测试范围：全部 9 个功能页面 + 典型小白问法（口语化、错别字、模糊请求、无关问题、英文提问）。
> 测试日期：2026-09-06 · 测试环境：UI :8501 / API :8000 / GTX 1060 4GB / NF4 量化
> 流程约定：**先集中记录、再一次性批量修复、最后回归验证**（本文档"修复状态"列为最终结果）。

## 问题清单

### A. 问答准确性（对小白伤害最大）

| 编号 | 严重度 | 页面 | 复现步骤 | 小白看到的现象 | 期望 |
|---|---|---|---|---|---|
| A1 | 🔴 严重 | 智能问答 | 先问"redis为啥那么快啊"，再问"**帮我总结一下这个知识库里都有什么**" | 模型无视新问题，把**上一轮 Redis 的回答**重新"总结"了一遍，语气肯定，耗时 42s | 要么给出基于知识库的概览，要么明确说"无法做整体总结，请具体提问" |
| A2 | 🔴 严重 | 智能问答 | 直接问"**红烧肉怎么做？**"（知识库里没有菜谱） | 模型凭空编造完整菜谱（腌制/煎炒/炖煮步骤全有），末尾还挂了一条**不相关的 RAG 引用** [1]。小白会以为菜谱来自知识库 | 诚实拒答："知识库中无相关内容" |
| A3 | 🟠 中 | Agent | 进入 Agent 页问"**今天几号？**" | 回答"**2023年4月1日**"（实际 2026-09-06），底部显示"步数 5 · 工具 0"——明明有 `get_current_time` 工具却一次都没调用，日期是模型瞎编的 | 调用时间工具或注入当前日期后回答正确 |
| A4 | 🟠 中 | 智能问答 | 问"String、StringBuffer、StringBuilder 有什么区别？"（知识库内有原文） | 三者定义正确，但"适用场景"的**成对对应关系被颠倒**（原文：单线程→StringBuilder、多线程→StringBuffer）。换温度、加 prompt 约束后复现 3 次 | 与原文一致的对应关系；确认是 1.5B 模型能力边界（见"遗留问题"） |
| A5 | 🟠 中 | 智能问答 | 观察回答下方的校验徽标 | 显示"⚠️ 部分内容可验证"或"❌ 未通过可验证性校验"，**没有任何解释**：是什么意思？哪句话有问题？该不该信？ | 徽标旁有通俗解释；能定位到可疑内容 |
| A6 | 🟡 低 | 智能问答 | 点开"📎 查看 8 条引用" | 一次列出全部 8 条检索结果，多数与答案无关；引用标题常是"Q50. …"这类原文截断，无"按相关度排序"说明 | 默认展示最相关的少数几条，说明排序含义 |

### C. 功能缺陷 / 危险操作

| 编号 | 严重度 | 页面 | 复现步骤 | 现象 | 期望 |
|---|---|---|---|---|---|
| C1 | 🔴 崩溃 | 文档版本 | 选择只有 1 个版本的文档（如 C#课程报告） | 整页崩溃：`StreamlitValueAboveMaxError: The value 3 is greater than the max_value 1`，出现裸异常堆栈。根因：`ui/page_modules/versions.py:204` `number_input(max_value=len(versions), value=3)` | 页面正常渲染，"保留最近"默认值不超过现有版本数 |
| C2 | 🔴 危险 | 知识库管理 | 点击任意文档旁的"🗑 删除" | **无任何二次确认，点击立即删除该文档全部分块**（如 fde面试题 214 块）。误触即数据丢失，小白无从恢复 | 至少一步确认（如勾选"我确认删除"）+ 明确后果提示 |
| C3 | 🟠 中 | 知识图谱 | 打开页面 | 实体数量 0、关系数量 0，无任何"为什么是空的/怎么构建"引导；页面上反而最显眼的是"🗑 清空图谱（谨慎操作）"按钮 | 空状态给出构建指引（`python scripts/build_kg.py`）；图谱为空时隐藏/禁用清空按钮 |
| C4 | 🟠 中 | 评估 | 看到唯一的"▶️ 运行评估"按钮 | 无时长/资源警告。实际会占满 GPU 数分钟，期间问答全部卡顿，小白以为死机 | 按钮旁说明预计耗时与影响，建议空闲时运行 |
| C5 | 🟡 低 | 智能问答 | 点击"🧹 清空对话" | 对话确实清空了，但**没有任何成功提示**，小白不确定是否点到了 | 显示"对话已清空" |
| C6 | 🟡 低 | 文档上传 | 观察 | 上传框写"Limit 200MB per file"（Streamlit 默认值），而 config 里 `max_upload_mb: 50` 从未被读取（死配置）；另：老 `.doc`/`.xlsx` 不支持，但页面不说不支持时会怎样、该怎么转 | 两处限制一致；写明"老 .doc 请先另存为 .docx"等指引 |

**修复过程中的关键发现（记录备查）**：
1. Streamlit 热重载只重新执行入口脚本 ui/app.py，`src/` 下已导入的模块**不会**重新加载——改 src 后必须杀进程重启（本轮 A2 首次验证失败即因于此）。
2. 重排器（bge-reranker）的 0~1 相关度分对"相关 vs 无关"有近乎完美的分离度（>0.9 vs <0.1），是低资源 RAG 最可靠的拒答信号，比向量余弦分和生成后校验都可靠。
3. 杀后台进程要按 netstat 监听 PID 精确杀；wmic 命令行 grep 会混入路径里的数字。

## 遗留问题（不属本轮"可一次性修复"范围）

1. **A4 对比类成对映射颠倒**：1.5B 模型能力边界。可选方案：升级 Qwen2.5-3B-Instruct（NF4 后约 2GB，本卡可容纳，代价是显存更紧张）；或对对比类问题启用"原文摘录模式"（检索到即原文返回，不生成）。
2. **多轮中小模型冗余重答上一题**（观察到一次）：候选方案 `memory.session_turns: 2` 已改，若仍出现可在历史注入时只保留上一轮 user+assistant。
3. **检索分数阈值与编造之间的平衡**：min_score 提高会增加"该答不答"，维持 0.25 保守值 + 靠拒答 prompt 与徽标提示，是低资源下的务实取舍。
