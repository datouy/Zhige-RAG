1. 身份与访问：企业模式强制认证；密码安全存储；登录失败限制；会话过期与注销；管理员可停用账号；普通用户、知识库管理员、系统管理员、审计员职责分离。优先复用企业现有 OIDC/LDAP/AD；没有 IdP 时提供安全的本地账号方案。

## 这套提示词相对原三步的改进

1. 把“最终目标”从一句抽象标准拆成可验收的产品边界、角色、数据边界、容量、SLO、灾备和运行条件。
2. 把“深挖”落成证据优先级、主张台账、基线复现、关键数据复算、反证清单和企业验收攻击场景。
3. 把“借力”分别映射到项目管理、风险、安全、SRE、测试、数据治理和发布管理，并要求产生代码、测试、脚本或 Runbook。
4. 明确“中型企业”不等于大型 SaaS：优先采用单企业私有化、部门/角色/知识库 ACL，不强制引入无证据支持的跨租户平台化改造。
5. 同时保留个人本地模式与企业模式，避免为了企业安全破坏项目原有的零门槛启动能力。
6. 增加执行纪律，防止助手只输出计划、伪造性能数据、通过关测试过验收或把配置存在误认为生产可用。

## 2026-11-23 项目基线快照

以下事实用于校验提示词是否贴合当前仓库；再次执行时必须复核。

- 主实现位于 `ChineseRAGKB/`，根目录其余论文、论文优化脚本、`_work/` 快照和未跟踪的 `Zhige-RAG/` 混在同一工作区，不能混读为主代码。
- Git 当前为 `main`，相对 `origin/main` 领先 15 个提交，且存在未跟踪目录；修改前必须保留现场。
- 当前服务把全部请求映射到一个固定的本地管理员用户，不提供登录、注册或按真实用户隔离；README 明确说明默认无认证。
- 现有主要能力包括多知识库、会话、文档上传/网页导入、混合检索、可选 GraphRAG、Agent、反馈、评估、限流、指标和 K8s 清单。
- Chroma 和用户级知识图谱使用本地单写持久化，K8s Deployment 固定 `replicas: 1`，HPA 也为 `minReplicas: 1 / maxReplicas: 1`。
- 模型设置接口会把覆盖配置写入 `config/local_overrides.yaml`，相关代码此前允许写入 API Key；企业模式需要重新审计密钥落盘、访问控制和轮换。
- CI 有 lint、语法、迁移、全量单测和评估步骤，但检索评估门禁当前使用 `continue-on-error: true`，不能视作硬性上线门禁。

- 项目已有大量具有实际价值的实现，方向不是“推倒重来”；更合理的路径是补齐企业模式、权限/隔离、运维闭环、真实压测和可验证质量门禁。
